Set up Zeitspiegel at your studio

Total time: about 30 minutes of computer work, plus shipping time for the parts. The flashing tools run on macOS or Linux; everything else is plug and play.

1. What to buy

Total parts cost is roughly €120–€180, plus a screen.

PartNotes
Raspberry Pi 5 (4 GB is fine; 8 GB if you want long buffers) The brain. Get the 4 GB for normal use; the 8 GB is only worth it if you want delays longer than a minute or two at 1080p.
raspberrypi.com · find a reseller
Official Raspberry Pi 5 power supply (27 W / 5 V 5 A USB-C) Required, not optional — the camera draws power from the Pi and the video encode pushes all four cores. Third-party USB-C bricks tend to be 3 A and will brownout under load.
search
Active cooler for Pi 5 The official one with the small fan is fine. Without it the Pi throttles during MP4 export.
search
micro-SD card, A2 rating, 16 GB or more Any reputable brand (SanDisk, Samsung, Kingston). The whole appliance fits in < 4 GB; the rest is headroom.
A wide-angle USB webcam (~100° diagonal, focus that stays put, native MJPEG) — around €30–€55 Three things matter, in this order. It must output MJPEG natively — that's the one requirement that can't be worked around, and a camera without it won't start at all. It should be wide, so the whole dancer fits from a couple of metres away. And its focus must stay where you put it, with no "AI" features — no auto-framing, no background blur, no beauty mode. Auto-framing is the worst offender: it would pan and crop the picture as you move.
Both fixed and manual focus are right for this. A fixed lens sits at its hyperfocal distance, so at 100° everything from about 30–40 cm out to infinity is sharp; a manual ring you set once at dancing distance does the same and cannot drift. Autofocus works too, but it has to be pinned in the config from a measured value, and that's one more thing to get wrong.
The current pick is the LogiLink UA0378 — 100°, manual focus, clips to a screen, tripod thread, about €34 (amazon.de B08QCXMC1V). Webcam listings churn constantly, so check the ranked shortlist — stock webcams and bare camera modules, with prices, the field-of-view maths and the named models to avoid — before ordering: docs/HARDWARE.md
Don't buy 4K. The Pi can't decode it fast enough for a live mirror, and it would be scaled back down anyway — you'd pay for resolution the appliance can never use.
Micro-HDMI → HDMI cable The Pi 5 has micro-HDMI sockets. One cable is enough.
Any HDMI display Whatever screen you want to use as the mirror. A 32" TV is a good starting size; bigger is better if guests will read it from across the room.
You'll also need: a way to mount the camera near or on the screen, pointed at where dancers will stand. Many studios use a small desktop tripod sitting on top of the TV, or a clamp on a mic stand.

2. What you need on your computer

Flashing the SD card is done from your Mac (or any Linux machine — see the note below). You need:

  • Docker Desktop — the image is baked inside a Linux container, so the recipe is the same on any host. docker.com.
  • Git — usually already installed; if not, install Xcode Command Line Tools (xcode-select --install) or git-scm.com.
  • Go 1.25 or newer — used to cross-build the Pi binary. go.dev/dl.

Not on macOS? The baking step works anywhere Docker runs. Writing the card is the only Mac-specific bit (make sd); on Linux, after make image, write the resulting build/zeitspiegel-appliance.img with dd or with the Raspberry Pi Imager's "Use custom image" option. Then mount the card's FAT32 bootfs partition and name the unit with scripts/stage-name.sh "Long Side" /path/to/bootfs — skip that and the mirror names itself after the Pi's serial number.

3. Get the code and flash a card

git clone https://github.com/DanielMSchmidt/zeitspiegel.git
cd zeitspiegel

Insert your micro-SD card into your Mac, then give the mirror a name and write the card:

make sd NAME="Long Side"

That single command downloads Raspberry Pi OS Lite (cached for next time), cross-builds the Zeitspiegel binary, bakes everything into a finished image inside Docker, then asks you to confirm before erasing the card and writing the image.

NAME is required, and it's the label this unit shows in the web page — pick whatever the room calls that corner: Long Side, Barre, Studio 2. It only matters once you own more than one mirror, but it is easier to set now than later. If you'd rather not name it, make sd NAME=auto writes a card that calls itself Zeitspiegel <ID> after the Pi's serial number.

The name is the only thing that differs between cards — the image itself is byte-identical on every one. You can rename a card later without re-flashing it: put it in any computer and run scripts/stage-name.sh "New Name" /Volumes/bootfs.

If you want a different Wi-Fi name than the default zeitspiegel:

SSID=studio-mirror make sd NAME="Long Side"

Before it erases anything, make sd checks that the card is big enough for the image and that the image passed its runtime check at bake time. If either fails it stops and tells you, with the card untouched.

What gets baked in: the binary, ffmpeg, SDL2, the systemd service, and an open Wi-Fi hotspot. SSH is off by default — the appliance is meant to be re-flashed, not logged into. A random console password is generated and saved to build/credentials.txt in the repo; keep it for the rare case where you need to plug a keyboard into the Pi directly.

4. First boot

  1. Put the card into the Pi.
  2. Plug in the camera, the HDMI cable to your screen, and finally the power.
  3. Wait about three minutes. The Pi resizes its filesystem, starts the Wi-Fi hotspot, locks itself into read-only mode, and reboots a couple of times. No interaction needed.
  4. You're done when the Wi-Fi network zeitspiegel (or whatever name you chose) appears on your phone.

5. Use it

  1. Connect your phone to the Wi-Fi network zeitspiegel. There is no password.
  2. Your phone might warn "this network has no internet" — that's expected and correct. Stay connected.
  3. Open http://zeitspiegel.local in any browser. (If that doesn't resolve, try http://10.42.0.1.)
  4. Use the slider to set the delay. Use the download button to save the last clip to your phone.

Print the guest poster and tape it next to the screen so dancers know what to do.

6. More than one mirror

Bigger rooms often want two or three — one down the long side, one at the barre. There is nothing to configure: write every card the same way (make sd NAME="…", a different name each time) and plug them in. The image is identical on all of them; the name is the only difference.

  • Whichever unit comes up first hosts the zeitspiegel Wi-Fi; the rest find it and join as members. There's still exactly one network in the room, and the order you switch them on doesn't matter.
  • The web page shows one card per mirror, named the way you named them, each with its own delay slider, preview and clip download. Changing one doesn't touch the others.
  • If the hosting unit is unplugged, one of the others takes the network over within seconds and keeps the name zeitspiegel.local. Plug the old one back in and it rejoins as an ordinary member.
  • You can buy more units years later and they'll join the same way — no unit knows or cares how many exist.

Clip downloads are the one thing that competes for radio time. If several mirrors will be in one room, bake the cards on 5 GHz for more headroom: AP_BAND=a AP_CHANNEL=36 make sd NAME="Long Side".

7. Day-to-day operation

  • To start: plug in power. The full-screen mirror is up in about 20 seconds.
  • To stop: pull the plug. The storage is read-only; nothing gets corrupted.
  • To move it: it's a Pi, a camera and a cable. Pack it up, set it up somewhere else, plug it in. No reconfiguration needed.
  • To change settings or update: re-flash the SD card from your computer (make sd NAME="Long Side") and swap it. The appliance has no login on purpose.

8. When things go wrong

Start here: the card can tell you what happened. A unit that won't come up has no Wi-Fi and no screen, so there is nothing to log into. It doesn't need one — every boot writes what it did to the card's own boot partition. Power the unit down, take the card out, put it in your computer and run: 
make sd-logs
That produces one zip — the boot report, the unit's journal for that boot, the version it was running — which is enough to see whether the camera enumerated, whether a screen was detected, and what the service said before it gave up. It only reads the card; it never writes to it.
The Wi-Fi zeitspiegel doesn't appear after 5 minutes

Read the card with make sd-logs (above) — the boot report says whether the radio came up. The most common cause is a country code mismatch blocking it; re-bake the card with WIFI_COUNTRY=YourTwoLetterCode make sd NAME="Long Side".

If several mirrors are running, this may also be correct behaviour: only one unit hosts the zeitspiegel network and the others join it as members. One network for the whole room is the expected result.

The screen stays black

Read the card with make sd-logs. The boot report records whether the Pi found a display at all, whether the camera enumerated, and how many times the service restarted — which separates "no screen", "no camera" and "the program is crashing" without any guesswork.

If you need to watch a problem happen rather than read about it afterwards, write a development card: make sd-dev NAME="Bench". It's the same appliance with the read-only seal left off, so it keeps verbose logs across reboots and can save the frames it is actually displaying — both collected by the same make sd-logs. Because it isn't sealed, pulling its power can corrupt the card: it's a card for a workbench, not for a studio.

zeitspiegel.local doesn't resolve

Some phones and routers don't do mDNS. Use the fallback IP http://10.42.0.1 — this always works when you're on the appliance's Wi-Fi.

The mirror looks fine but the delay slider does nothing

Make sure you're connected to the zeitspiegel Wi-Fi (not your home or studio Wi-Fi) when you open the web page. The appliance is only reachable on its own network.

I need to change a setting (camera mode, buffer length, etc.)

The appliance is read-only by design and SSH is off, so the supported way to change settings is to edit deploy/config.toml in your local checkout, run make sd NAME="Long Side" again, and swap the card. Boot is fast enough that this is genuinely easier than logging in.

How do I update to a new version?

Easiest: git pull in your local checkout, run make sd NAME="Long Side" again, swap the card. The Pi treats it as a fresh boot. If you've configured anything custom on the device, back that up first.
